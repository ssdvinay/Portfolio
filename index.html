01 · Enterprise SaaS · Predictive Maintenance · Industrial UX

Rebootz.AI — Intelligent
Maintenance Platform

An enterprise-grade Intelligent Maintenance Management Platform (IMMS) enabling industrial organizations to shift from reactive to predictive maintenance — centralizing equipment lifecycle, spare parts, technician field operations, and SAP/ERP integration into one connected ecosystem across web and mobile.

Role
UI/UX Designer
Platforms
Web + Mobile
User types
5 distinct roles
Tools
Figma · FigJam
The challenge

From spreadsheets to predictive operations

Large industrial organizations relied on spreadsheets, manual reporting, and paper-based maintenance logs — creating frequent breakdowns, unplanned downtime, and no centralized view of equipment health across the plant.

Frequent machine breakdowns with no advance warning
No centralized asset information or maintenance history
Poor spare parts visibility leading to delayed repairs
Manual SAP/ERP synchronization causing data errors
Delayed maintenance scheduling and compliance tracking
High maintenance costs from reactive-only operations
Users

Five roles, two platforms

The platform needed to serve desk-based managers planning work and field technicians completing it on a factory floor — a fundamental split that shaped the entire web vs. mobile strategy.

01
Maintenance Managers
Monitor assets, approve work orders, schedule maintenance, and analyze KPIs — primarily on web.
02
Field Technicians
Receive assignments, inspect equipment, complete maintenance, and update status directly from mobile on-site.
03
Inventory Managers
Track spare parts availability, allocate inventory, and manage reordering — on web.
04
Plant Managers
View operational dashboards, monitor downtime trends, and evaluate performance — on web.
05
System Administrators
Manage users, permissions, master data, and enterprise integrations — on web.
Web portal · Admin dashboard

Operational command center

The dashboard had to answer one question instantly: is anything about to break? I designed it around layered KPI cards — total, open, and closed work orders plus notifications — each broken down by maintenance type (Preventive, Reactive, Predictive) so managers see both volume and nature of work at a glance.

Admin Dashboard — KPI cards by maintenance type · Work Order Distribution analytics

Below the KPI row, the Work Order Types Distribution chart breaks data down by status (Total, Completed, In Progress, Open) — letting a manager pivot from "how much work exists" to "where is it stuck" without leaving the screen.

Web portal · Maintenance plan

Scheduling preventive work visually

Preventive maintenance only works if scheduling is genuinely easier than skipping it. I designed the Maintenance Plan as a weekly calendar where every task is colour-coded by priority (High, Medium, Low) and shows live status (Active / Inactive) directly on the card — so a manager scanning the week can spot a high-priority inactive task instantly without opening it.

Maintenance Plan — weekly view with priority color-coding and overflow handling
Web portal · Onboarding

Bringing technicians into the system

Administrator onboarding uses a card-grid layout rather than a dense table — since onboarding is a low-frequency, high-care task where administrators are verifying a handful of people at once, not scanning hundreds. Individual identity cards with photo, department tag, and a clear action made more sense than a compressed list.

Onboarding — technician cards grouped by department with clear status indicators
Mobile app · Core screens

Designed for the factory floor

The mobile app exists so a technician never walks back to a desktop to log work. Every screen was designed for field conditions — quick to read at a glance, fast one-handed, and forgiving of interruption. I carried the same design system from web but restructured the information hierarchy entirely around task-first navigation.

Splash screen
Sign in
Technician dashboard

The technician dashboard surfaces four numbers immediately — Total Tasks, Completed, In Progress, Overdue — each with a trend indicator, followed by a Task Distribution donut chart. This mirrors the web admin dashboard's KPI-first pattern deliberately, so switching between platforms feels familiar.

Mobile app · Field tools

Calendar, barcode scan & identity

Calendar — daily task list
Barcode asset scan
Profile & 2FA

The scan screen uses a large, high-contrast target frame and a single "Tap to Scan" — deliberately minimal, since this is often used quickly, sometimes with gloved hands or in inconsistent factory lighting where every extra element is friction.

02 · Enterprise SaaS · RPA · SAP Integration · B2B Platform

MUNTQ — Enterprise Automation
& Intelligence Platform

A confidential enterprise automation platform unifying business intelligence reporting, robotic process automation, AI-powered document processing, SAP integration, and organizational governance — turning fragmented, manual operations into one traceable, automated system.

Role
UI/UX Designer
Platform
Web Portal
Modules
7 core systems
Tools
Figma · FigJam
The challenge

Operations scattered across spreadsheets and inboxes

Organizations were running critical processes like order-to-cash through email inboxes and manual SAP data entry. Approvals happened in email threads, exceptions had no resolution path, and there was no centralized view of operational performance.

Manual order entry from email PDFs into SAP, line by line
No centralized KPI dashboards across business functions
Failed automations with no clear path to human resolution
POs requiring complex partial-shipment handling
No unified approval governance across departments
No audit trail for compliance-sensitive transactions
Users

Six roles across the enterprise

MUNTQ is not built for one department. Designing role-based access meant every screen had to answer: "who is looking at this, and what exactly do they need to decide?"

01
Business Analysts
Monitor dashboards, review KPIs, configure workflows — need department-level reporting and process visibility.
02
Operations Teams
Manage incoming requests, validate documents, review exceptions — need fast issue resolution and clear task ownership.
03
Functional Consultants
Troubleshoot automation issues, correct data mappings — need error diagnostics and Action Center tools.
04
Procurement & Supply Chain
Manage POs, vendor workflows, condition records — need vendor filtering and partial-shipment handling.
05
Enterprise Administrators
Manage users, roles, permissions, governance — need system-wide control and audit history.
06
Executives & Leadership
Need high-level performance visibility, bottleneck alerts, and strategic reporting — not operational detail.
Reporting module

One shell, four business domains

Rather than four separate dashboard products, I designed a single dashboard shell where a top-level dropdown switches KPIs, charts, and filters based on business area. The right-hand AI Insights panel surfaces anomalies automatically — instead of requiring analysts to notice issues by scanning tables, the system names them plainly and explains them.

Reporting · Sales Dashboard — KPI cards, trend analysis, and AI Insights panel
RPA module · Dashboard

Is the automation layer healthy?

The RPA dashboard answers a different question than the business dashboards: not "how is the business performing" but "is the automation itself running?" I designed it around system health KPIs — Active Automations, Success Rate, Failed Runs, Average Execution Time — paired with a live activity feed and a failed runs table that links directly into the Action Center.

RPA Dashboard — automation health metrics with live activity feed and failed runs log
RPA module · Scenario library

Start from a template, not a blank canvas

Most users never need to build from scratch. I designed a Scenario Library of pre-built automation templates — each showing apps connected and estimated time saved per week — so a business analyst can deploy an automation in minutes. Selecting a template opens a plain-language detail screen before committing to the visual builder.

Scenario Library — pre-built templates with time savings and one-click deployment
Scenario detail — plain-language breakdown before the visual canvas
RPA module · Builder canvas

Visual automation for business users

The visual canvas reads left-to-right like a sentence: trigger → process → validate → post. Every node shows its application icon, action name, and a one-line description on-canvas, so anyone reviewing the flow understands it without clicking into a single node — which matters when you're accountable for a flow you didn't build.

Scenario Builder — Email Order-to-Cash flow: Outlook → AI Extract → Validate → SAP
RPA module · Condition records

Handling partial shipments without losing the thread

In real procurement, shipments arrive in partial batches. I surfaced Submitted and Pending as separate columns in the listing table — because the real question for a procurement user isn't "is this PO done?" it's "how many of these 24 lines still need me?" A small progress indicator on each row makes the status impossible to miss.

Condition Records — vendor-filtered PO listing with per-row submitted vs. pending counts
Administration

User management & governance

Because MUNTQ's permissions span multiple modules independently, the admin table shows role and module access together. Status uses four distinct visual states — Active, Pending Invite, Suspended, Inactive — with semantic colors, so an administrator can spot a suspended account without reading every row.

User Management — module-level access as tags independent of job title
Login

Trust before entry

For software handling SAP transactions and financial data, the login screen needs to signal seriousness immediately. I paired a clean form with a deep brand panel stating the platform's core value in plain language — Enterprise Intelligence, Unified — before the user has even authenticated.

Login — enterprise trust signal before authentication
Outcome

Automate workflows. Govern decisions.

Manual data entry
↑
Process traceability

  • Business analysts can deploy automations without technical support via the template library
